# F10 VSCode Tool 测试与发布指南

## 一、如何测试

### 1. 本地调试（开发期最常用）

```bash
cd vscode-plugin/f10-vscode-tool
npm install      # 第一次需要
npm run build    # 或 npm run watch 监听式编译
```

用 **VSCode 打开 `f10-vscode-tool` 这个目录**（不是项目根，是插件子目录），按 **F5**（或菜单 Run → Start Debugging）。

VSCode 会启动一个新窗口，标题栏显示 `[Extension Development Host]`，插件在这个新窗口里运行。

在新窗口里测试：

- 打开一个**真实的 F10 工作区文件夹**（比如 `vue-frame-live-docs` 仓库本身），这样 `getWorkspaceRoot()` 才有值
- 左侧活动栏会多一个三角形图标（F10 VSCode Tool），点进去能看到树
- 点叶子节点（环境安装 / 添加私有源 / 启动工程等）就会执行对应命令

调试时可以在 `src/extension.ts` 等文件打断点，断点会被命中。改完代码后：

- 用了 `npm run watch` 的话直接重新加载窗口（Ctrl+R / Cmd+R）即可
- 用了 `npm run build` 的话先重跑 build，再 reload 窗口

### 2. 冒烟测试脚本

已有两个不依赖 VSCode 环境的脚本，可以单独跑：

```bash
node scripts/smoke-test.js          # 验证 zip 工具
node scripts/upload-smoke-test.js   # 验证 multipart 上传
```

两个都通过才能确认核心工具方法 OK。

### 3. 手动验证清单

在 Extension Development Host 窗口里按顺序过一遍：

| 命令 | 怎么验证 |
|------|---------|
| 环境安装 | 弹窗"继续/查看脚本"，选"查看脚本"应能看到对应平台脚本文件；选"继续"会在终端依次跑 nvm → Node → nrm → epoint 源 → pnpm@10 → eui-cli，最后提示用户 `npm login` |
| 添加公司私有源 | 弹窗确认后终端执行 `npm i -g nrm` → `nrm add epoint` → `nrm use epoint`，并提示用户继续 `npm login` |
| 安装 eui-cli | 终端执行 `npm install -g @epframe/eui-cli` |
| 创建工作区 | 集成终端跑 `eui-cli ws`（需要本机已装 eui-cli） |
| 创建 web/comp | 终端进入 `eui-cli web` / `eui-cli comp` 交互；执行后弹窗给出"开启 Mock 模式"或"接入组件工程"快捷入口 |
| 开启 Mock 模式 | 选 web 工程后自动把 `src/config.js` 的 `isMock: false` 改为 `true`，幂等 |
| 接入组件工程 | 选 web 工程 + 组件工程，自动改 `package.json.dependencies` 与 `src/setup.js` 的 import 与 `deps` 数组 |
| 新增页面 | 选组件工程后输入相对路径（如 `demo/index`），生成 `src/views/<相对路径>.vue` |
| 安装依赖 | 终端跑 `pnpm install` |
| 编译所有包 | 终端跑 `eui-cli build` |
| 启动工程 | 自动扫描出含 dev 脚本的工程让你挑一个，进入并跑 `pnpm run dev --force` |
| 打包部署 | 同上，进入工程跑 `pnpm run build` |
| 上传应用 | 先点"设置"创建 `f10-tool.config.json`，至少填 `uploadUrl` 与 `sdocKey`，再点上传，看 OutputChannel 输出。`sdocKey` 为空会弹错"请前往魔方平台创建应用获取应用 key" |

> F10 工程内（pnpm workspace + 同时存在 web 工程与组件工程）会自动把"初始化"分组下的命令置灰，避免误操作。「配置接入」与「开发」「部署」分组不受影响。

### 4. 测试上传功能

不用真连内网，可以本地起个 echo server 验证：

```bash
# 临时起个接收上传的小服务
node -e "require('http').createServer((req,res)=>{let n=0;req.on('data',c=>n+=c.length);req.on('end',()=>{console.log('got bytes:',n);res.end('{\"ok\":true}')})}).listen(3000,()=>console.log('listening on 3000'))"
```

然后 `f10-tool.config.json` 里 `uploadUrl` 填 `http://127.0.0.1:3000/upload`，跑一次"上传应用"，能看到 OK 即成功。

## 二、如何发布

VSCode 插件有三种主流分发方式，按团队场景选。

### 方式 A：打包成 .vsix 内部分发（推荐公司内网使用）

公司内网项目通常不上架公共市场，做成 vsix 文件丢到群里 / Nexus / 内网 wiki 让大家手装最省事。

```bash
cd vscode-plugin/f10-vscode-tool
npm install -g @vscode/vsce         # 一次性安装打包工具
npm run package                     # 生成 f10-vscode-tool-1.0.0.vsix
```

`vsce package` 第一次会要求你完善 `package.json`：

- `publisher` 字段必须有（已经填了 `epoint-fe`，不上市场可以随便取）
- `repository` / `license` / `README.md` 不要为空

打出来的 `.vsix` 团队成员安装方式：

- VSCode → 扩展面板 → 右上 `…` → **"从 VSIX 安装..."** → 选文件
- 或命令行：`code --install-extension f10-vscode-tool-1.0.0.vsix`

#### 推荐的内部发布流程

1. 第一次上架：
   ```bash
   npm run build
   npm run package      # 产出 vsix
   ```
2. 把 `f10-vscode-tool-x.y.z.vsix` 上传到公司内网（Nexus 也支持 raw 仓库）
3. 写个一行的安装命令丢到内部文档里：
   ```bash
   code --install-extension http://192.168.0.99:8081/.../f10-vscode-tool-1.0.0.vsix
   ```
4. 后续迭代：改 `package.json` 的 `version` → `npm run package` → 替换文件即可，VSCode 装新版会自动覆盖旧版

### 方式 B：上架 VSCode Marketplace（公开发布）

只有想给全世界用才需要这个。流程：

```bash
# 1. 在 https://marketplace.visualstudio.com/manage 创建 publisher
# 2. 在 https://dev.azure.com/ 创建 PAT (Personal Access Token)
#    权限选 Marketplace > Manage
# 3. 登录
vsce login epoint-fe   # publisher 名字
# 输入 PAT

# 4. 发布
vsce publish           # 走 package.json 的 version
vsce publish minor     # 自动 +0.1.0 后发
vsce publish 1.0.1     # 直接发指定版本
```

> 注意上架公共市场需要 `repository` 是真实可访问的公开仓库，对内网项目不适用。

### 方式 C：上架 Open VSX（VSCode 衍生 IDE 用，如 Cursor/Theia）

```bash
npm install -g ovsx
ovsx publish -p <token>
```

通常和 marketplace 一起发，扩展面更广。

## 三、上传 zip 的实现原理

这块做了**零运行时依赖**的实现，避免插件打包后还要拖 archiver、form-data 这种 native 库。

### 1. zip 打包：`src/utils/zip.ts`

ZIP 格式是一个简单的二进制容器，结构如下：

```
[本地文件头1][文件1压缩数据]
[本地文件头2][文件2压缩数据]
...
[中央目录头1][中央目录头2]...
[中央目录尾记录 EOCD]
```

实现要点：

#### CRC32 计算

ZIP 每个文件需要一个 CRC32 校验值。Node 标准库没有 CRC32，所以预生成 256 项的 CRC 查表，然后逐字节累计：

```ts
const CRC_TABLE = (() => {
  const table = new Uint32Array(256);
  for (let i = 0; i < 256; i++) {
    let c = i;
    for (let k = 0; k < 8; k++) {
      c = (c & 1) ? (0xedb88320 ^ (c >>> 1)) : (c >>> 1);
    }
    table[i] = c >>> 0;
  }
  return table;
})();

function crc32(buf: Buffer): number {
  let c = 0 ^ -1;
  for (let i = 0; i < buf.length; i++) {
    c = (c >>> 8) ^ CRC_TABLE[(c ^ buf[i]) & 0xff];
  }
  return (c ^ -1) >>> 0;
}
```

#### 压缩策略

用 Node 自带的 `zlib.deflateRawSync` 做 deflate 压缩。如果压缩后比原文件还大（小文本/已压缩资源很常见），就退回 store 模式（不压缩），这是 ZIP 规范允许的：

```ts
const compressed = zlib.deflateRawSync(raw, { level: zlib.constants.Z_BEST_SPEED });
if (compressed.length < raw.length) {
  data = compressed;
  method = 8; // deflate
} else {
  data = raw;
  method = 0; // store
}
```

#### 拼装三段二进制

- 每个文件写一段 30 字节的 **Local File Header**（魔数 `0x04034b50` + 版本 + flag + 压缩方法 + crc + 原大小 + 压缩后大小 + 文件名长度 + 文件名 + 数据）
- 所有文件写完后写 **Central Directory**（46 字节头 + 文件名）
- 最后写 22 字节的 **EOCD**（魔数 `0x06054b50` + 中央目录大小和偏移）

#### 递归遍历

用 `fs.readdirSync` 递归扫描 dist 目录，相对路径用 `/` 分隔（ZIP 规范要求），这样在 Linux/Windows 系统都能正常解压。

#### UTF-8 文件名支持

通用标志位（flag）的第 11 位（`0x0800`）置 1，告诉解压器"我的文件名是 UTF-8"，避免中文文件名乱码。

最终拼接成一个 Buffer 写盘：

```ts
const allBuffers = [...localBuffers, ...centralBuffers, eocd];
fs.writeFileSync(outputZip, Buffer.concat(allBuffers));
```

### 2. multipart 上传：`src/utils/upload.ts`

`multipart/form-data` 协议本质是个文本边界协议，不需要库也能拼。

#### 生成边界字符串

每次请求用一个不会和文件内容冲突的随机串：

```ts
'----F10VSCodeBoundary' + Math.random().toString(16).slice(2) + Date.now().toString(16)
```

#### 逐段拼接 Buffer

```
--boundary\r\n
Content-Disposition: form-data; name="appName"\r\n
\r\n
demo-web\r\n
--boundary\r\n
Content-Disposition: form-data; name="version"\r\n
\r\n
1.0.0\r\n
--boundary\r\n
Content-Disposition: form-data; name="file"; filename="demo-web-1.0.0.zip"\r\n
Content-Type: application/zip\r\n
\r\n
<二进制 zip 数据>\r\n
--boundary--\r\n      <- 注意结尾多两个减号
```

每个文本段直接 `Buffer.from(..., 'utf-8')`，文件段 `fs.readFileSync` 读出来当原始 Buffer 拼接。

#### 发请求

用 Node 自带的 `http`/`https`，根据 URL 协议选一个：

```ts
const req = lib.request({
  method: 'POST',
  hostname, port, path,
  headers: {
    'Content-Type': `multipart/form-data; boundary=${boundary}`,
    'Content-Length': body.length,
    ...userHeaders   // 允许配置里加 Authorization
  }
}, res => { ... 收响应 ... });
req.write(body);
req.end();
```

#### 响应处理

把所有 chunks 拼起来 toString，连同 statusCode 返回，让上层决定怎么展示给用户。

### 3. 整体上传流程（`src/commands/uploadApp.ts`）

```
读 f10-tool.config.json
   ↓
判断 dist 目录在哪（先工作区根，再让用户挑 web 工程）
   ↓
zipDirectory(distDir, .f10-upload/<appName>-<version>.zip)
   ↓
uploadFile({ url, filePath, fileField, fields: { appName, version, ...extra }, headers })
   ↓
HTTP 200~299 → 提示成功，否则提示失败
   ↓
所有过程日志写入 OutputChannel "F10 VSCode Tool"
```

### 4. 设计优势

- **无第三方依赖**：插件打包后大小才 16KB（`dist/extension.js`），不带 node_modules 也不掉文件
- **流式可控**：所有错误都进 OutputChannel，便于排查
- **配置驱动**：换个项目改 `f10-tool.config.json` 即可，URL/版本/字段全在配置里
- **跨平台**：ZIP 路径分隔符统一用 `/`，UTF-8 文件名标志位正确设置

## 四、上传配置文件说明

上传命令依赖工作区根下的 `f10-tool.config.json`，结构如下：

```json
{
  "uploadUrl": "http://your-server.example.com/api/app/upload",
  "appName": "demo-web",
  "version": "1.0.0",
  "sdocKey": "",
  "distDir": "dist",
  "fileField": "file",
  "extraFields": {
    "channel": "beta"
  },
  "headers": {
    "Authorization": "Bearer xxxxx"
  }
}
```

| 字段 | 必填 | 默认 | 说明 |
|------|------|------|------|
| uploadUrl | ✅ | - | 后端接收上传的接口地址 |
| appName | ✅ | - | 应用标识，会作为 form-data 字段一起上传 |
| version | ✅ | - | 版本号，会作为 form-data 字段一起上传 |
| sdocKey | ✅ | - | 魔方平台应用 Key，未填会弹错"请前往魔方平台创建应用获取应用 key"，作为 form-data 字段一起上传 |
| distDir | ❌ | dist | 待打包的目录名 |
| fileField | ❌ | file | multipart/form-data 中文件字段名 |
| extraFields | ❌ | {} | 额外要附带的表单字段 |
| headers | ❌ | {} | 额外的 HTTP 请求头（如鉴权 token） |

## 六、命令速查

侧边栏分组 → 命令列表（命令面板里都加了 `F10:` 前缀）：

| 命令 | 命令 ID | 行为 |
